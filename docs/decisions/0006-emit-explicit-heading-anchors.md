# ADR-0006: Emit explicit heading anchors for resolved internal links

- **Status:** Accepted
- **Date:** 2026-09-28

## Context

PDF internal links target page destinations rather than Markdown headings.
After analysis matches a visible link label to a semantic heading, Markdown
needs a stable fragment identifier. Markdown does not standardize generated
heading identifiers, and renderer-specific slug algorithms differ in
punctuation, Unicode, duplicate handling, and future compatibility.

## Decision

Resolved internal destinations receive deterministic, document-unique anchors
derived from normalized semantic heading text. The Markdown renderer emits an
explicit `<a id="..."></a>` element immediately before each referenced ATX
heading and links to that fragment.

Anchor identifiers contain only Unicode letters, digits, and hyphens. Duplicate
base identifiers receive a deterministic numeric suffix in document order.
The renderer emits internal links only when the target matches an emitted
anchor; unresolved targets retain visible unlinked text.

Raw HTML remains prohibited as a fallback for uncertain document content.
This decision permits only the fixed, validated anchor element generated by
the renderer.

## Consequences

- Internal links do not depend on a Markdown host's implicit heading-slug
  algorithm.
- Anchors remain stable while the normalized heading text and document order
  remain stable.
- Markdown consumers that disable raw HTML may display the headings normally
  but may not provide working internal links.
- Explicit anchor lines add small, predictable markup before referenced
  headings.

## Alternatives considered

- **Rely on implicit heading identifiers:** rejected because Markdown does not
  standardize them and duplicate or Unicode headings vary across renderers.
- **Use attribute-list syntax such as `{#id}`:** rejected because it is a
  non-standard extension with less consistent support than HTML anchors.
- **Link only to page numbers:** rejected because Markdown has no portable
  page concept.
- **Drop all internal links:** rejected because reliable PDF destinations and
  semantic headings provide enough evidence to preserve useful navigation.
